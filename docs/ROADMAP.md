# نقشه راه پیاده‌سازی UniMate

ساختار پروژه (monorepo با npm workspaces):

```
unimate/
├─ apps/
│  ├─ web/        ← Next.js + TypeScript          (مرحله ۱)
│  └─ mobile/     ← React Native + Expo           (مرحله ۷)
├─ packages/
│  └─ shared/     ← تایپ‌های دیتابیس، اعتبارسنجی، کوئری‌های مشترک
├─ supabase/
│  ├─ config.toml
│  ├─ migrations/ ← اسکیمای دیتابیس + RLS
│  └─ tests/      ← تست‌های RLS (بدون نیاز به Docker)
└─ docs/
```

اصل کلیدی: **همهٔ قوانین دسترسی در دیتابیس (RLS) اعمال می‌شوند**، نه در UI.
وب و موبایل فقط کلاینت هستند؛ حتی اگر کسی مستقیم به API بزند، نمی‌تواند از قوانین عبور کند.

---

## ✅ مرحله ۰ — زیرساخت و دیتابیس

- [x] ساختار monorepo، `.gitignore`، `.env.example`
- [x] پیکربندی Supabase (ایمیل/رمز + Google، آدرس‌های بازگشت وب و موبایل)
- [x] جداول: `profiles`, `classes`, `class_members`, `class_invites`, `join_requests`,
      `assignments`, `assignment_status`, `assignment_reports`, `personal_tasks`, `notifications`
- [x] RLS روی همهٔ جداول + محدودیت سطح ستون
- [x] RPCها: `get_invite_preview`, `request_to_join`, `respond_to_join_request`
- [x] تریگرها: ساخت خودکار پروفایل، عضویت مالک، اعلان‌ها
- [x] view `my_assignments` (تکالیف همهٔ کلاس‌ها + وضعیت شخصی)
- [x] Realtime برای تکالیف، اعضا، درخواست‌ها و اعلان‌ها
- [x] ۲۷ سناریوی تست RLS (`npm run test:db`)

## ✅ مرحله ۱ — اپ وب: پایه و احراز هویت

- [x] Next.js 16 (App Router، Cache Components) در `apps/web` + Tailwind 4 + RTL و فونت وزیرمتن
- [x] `@supabase/ssr` برای session در سرور و کلاینت؛ `proxy.ts` برای مسیرهای محافظت‌شده
- [x] صفحات ثبت‌نام، ورود، فراموشی رمز، تعیین رمز جدید، ورود با Google، `/auth/callback`
- [x] صفحهٔ پروفایل (نام، دانشگاه) و تغییر رمز عبور
- [x] تایپ‌های دیتابیس تولیدشده در `packages/shared`
- [ ] تست ورود با Google (نیازمند Client ID/Secret واقعی)

## مرحله ۲ — کلاس‌ها و عضویت

- ساخت کلاس (نام درس، استاد، ترم) و لیست کلاس‌های من
- مدیریت لینک دعوت: ساخت، تاریخ انقضا، سقف استفاده، لغو، کپی لینک
- صفحهٔ `/join/[token]`: پیش‌نمایش کلاس و ارسال درخواست عضویت
- صف درخواست‌ها برای مالک: تأیید / رد
- لیست اعضا، حذف عضو توسط مالک، ترک کلاس توسط عضو

## مرحله ۳ — تکالیف کلاس

- افزودن تکلیف (عنوان، توضیحات، مهلت، اولویت) توسط اعضا
- ویرایش/حذف (سازنده یا مالک)
- نمایش بلادرنگ تکالیف جدید (Supabase Realtime)
- گزارش تکلیف اشتباه + صفحهٔ بررسی گزارش‌ها برای مالک

## مرحله ۴ — پیگیری شخصی

- تغییر وضعیت شخصی: انجام‌نشده / در حال انجام / تکمیل‌شده
- داشبورد «کارهای من»: تکالیف همهٔ کلاس‌ها + کارهای شخصی
- CRUD کارهای شخصی

## مرحله ۵ — تقویم و برنامه‌ریزی

- نمای تقویم ماهانه/هفتگی بر اساس مهلت (با پشتیبانی تاریخ شمسی)
- مرتب‌سازی و فیلتر بر اساس مهلت، اولویت، کلاس و وضعیت
- برجسته‌سازی کارهای نزدیک به مهلت یا عقب‌افتاده

## مرحله ۶ — اعلان‌ها

- زنگوله اعلان با شمارندهٔ خوانده‌نشده (Realtime)
- لیست اعلان‌ها، علامت‌گذاری خوانده‌شده (تکی/همه)، لینک به مقصد هر اعلان

## مرحله ۷ — اپ موبایل (Expo)

- راه‌اندازی Expo + Expo Router در `apps/mobile`، استفادهٔ مجدد از `packages/shared`
- احراز هویت (ایمیل + Google با deep link `unimate://auth/callback`)
- همهٔ قابلیت‌های مراحل ۲ تا ۶ به‌صورت native
- باز کردن لینک دعوت در اپ (deep link)
- (اختیاری) Push notification با Expo Notifications

## مرحله ۸ — آماده‌سازی انتشار

- پروژهٔ Supabase ابری، `supabase db push`، تنظیم Google OAuth نهایی
- استقرار وب روی Vercel، بیلد موبایل با EAS
- بازبینی امنیتی، محدودیت نرخ، تست end-to-end
