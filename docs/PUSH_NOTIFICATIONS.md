# Push notification — بررسی گزینه‌ها

الان اعلان‌ها **داخل اپ و سایت** هستند: در جدول `notifications` ذخیره می‌شوند و با Realtime زنده نمایش داده می‌شوند، ولی فقط وقتی اپ یا سایت باز است. یادآوری کلاس و مهلت تکلیف را هم یک job در دیتابیس (`send_due_reminders`، هر ۵ دقیقه با pg_cron) در همین جدول می‌سازد.

برای این‌که اعلان **روی گوشی بیاید حتی وقتی اپ بسته است**، دو نوع نیاز داریم که راه‌حلشان فرق دارد:

| نوع | مثال | زمانش از قبل معلوم است؟ |
|-----|------|--------------------------|
| یادآوری | «کلاس پایگاه داده ۳۰ دقیقهٔ دیگر» · «مهلت تمرین فردا» | بله |
| رویداد | «تکلیف جدید» · «درخواست عضویت» · «درخواستت تأیید شد» | نه — وقتی کسی کاری می‌کند |

## گزینه‌ها

### ۱. اعلان محلی (Local notification) — فقط برای یادآوری‌ها

اپ خودش زمان‌بندی می‌کند (کتابخانهٔ متن‌باز `expo-notifications` یا `notifee`)؛ هر بار که اپ باز می‌شود، یادآوری جلسه‌های کلاس و مهلت‌های چند روز آینده را روی گوشی تنظیم می‌کند.

- ✅ بدون سرور، بدون حساب، بدون گوگل؛ در ایران و بدون اینترنت هم کار می‌کند.
- ✅ روی همهٔ گوشی‌ها (حتی بدون Google Play Services).
- ❌ فقط چیزهایی که اپ آخرین بار دیده: اگر بعد از آخرین باز شدن اپ، کسی تکلیف جدید بگذارد یا مهلت را عوض کند، یادآوری‌اش تا باز شدن بعدی اپ تنظیم نمی‌شود.
- ❌ برای رویدادها (تکلیف جدید، درخواست عضویت) کاری نمی‌کند.

### ۲. Firebase Cloud Messaging (FCM) مستقیم

سرویس رسمی گوگل که push اندروید (و Expo Push) در نهایت از آن عبور می‌کند. اپ توکن FCM گوشی را می‌گیرد (`getDevicePushTokenAsync` در `expo-notifications`، بدون سرور Expo) و در دیتابیس ذخیره می‌کند؛ یک Supabase Edge Function یا Database Webhook هنگام ساخت هر ردیف در `notifications` آن را با FCM HTTP v1 می‌فرستد.

- ✅ رایگان، بدون محدودیت عملی، استاندارد؛ هم یادآوری و هم رویداد.
- ✅ بدون وابستگی به Expo (فقط کتابخانهٔ متن‌باز روی گوشی).
- ❌ نیاز به پروژهٔ Firebase (حساب گوگل؛ ساختنش از ایران احتمالاً VPN می‌خواهد) و فایل `google-services.json` در اپ.
- ❌ گوشی باید Google Play Services داشته باشد (برخی گوشی‌های هواوی/شیائومی چینی ندارند).
- ⚠️ **در ایران:** اتصال گوشی به سرورهای FCM گاهی ناپایدار یا مسدود است؛ باید روی چند گوشی و اپراتور واقعی تست شود.

### ۳. سرویس ایرانی (پوشه / نجوا)

سرویس‌های push داخلی که برای شبکهٔ ایران طراحی شده‌اند (پوشه کانال اختصاصی خودش را دارد و FCM را هم به‌عنوان مسیر جایگزین استفاده می‌کند).

- ✅ معمولاً در ایران پایدارتر از FCM خالص؛ پنل فارسی و آمار.
- ❌ نیاز به حساب در آن سرویس، SDK بومی و API اختصاصی (وابستگی به یک شرکت)؛ پلن رایگان محدودیت دارد.
- ⚠️ سازگاری SDK آن‌ها با React Native 0.88 و معماری جدید باید قبل از انتخاب بررسی شود.

### ۴. Expo Push Service

ساده‌ترین راه در اکوسیستم Expo (یک API برای اندروید و iOS).

- ✅ پیاده‌سازی خیلی ساده.
- ❌ نیاز به حساب Expo و projectId (همان چیزی که نخواستیم)؛ برای اندروید در نهایت از FCM عبور می‌کند، پس مشکل ایران سر جایش است.

### ۵. Web Push (برای سایت)

اعلان مرورگر روی سایت، با service worker و کلیدهای VAPID (بدون سرویس شخص ثالث در سرور).

- ✅ برای کاربران وب؛ بدون نصب اپ.
- ❌ مرورگر کروم پیام را از مسیر سرویس push گوگل می‌گیرد (همان مشکل ایران)؛ روی iPhone فقط وقتی سایت به صفحهٔ اصلی اضافه شده باشد.

## پیاده‌سازی (انتخاب‌شده: اعلان محلی + FCM + Web Push)

### ۱. یادآوری‌ها — اعلان محلی (فعال، بدون تنظیم)

اپ اندروید (`apps/mobile/src/lib/phone-notifications.ts`) هنگام باز شدن، هر بار که به پیش‌زمینه برمی‌گردد، بعد از تغییر وضعیت تکلیف یا تنظیمات یادآوری، و وقتی اعلان زنده‌ای از دیتابیس می‌رسد (مثلاً تکلیف جدید)، یادآوری‌های **۷ روز آینده** را با زمان‌های انتخابی کاربر روی خود گوشی زمان‌بندی می‌کند. با لمس اعلان، صفحهٔ کلاس باز می‌شود. اولین بار اندروید ۱۳+ اجازهٔ اعلان می‌پرسد. هنگام خروج از حساب، یادآوری‌ها پاک می‌شوند.

اپ بعد از هر زمان‌بندی، فهرست یادآوری‌هایی را که خودش تنظیم کرده در جدول `phone_reminders` گزارش می‌کند. وقتی `send_due_reminders` (هر ۵ دقیقه روی سرور) یادآوری‌ای می‌سازد که در آن فهرست **نیست** — مثلاً مهلت تکلیفی که وقتی اپ بسته بوده اضافه یا عوض شده — `send-push` آن را با FCM به گوشی می‌فرستد؛ بنابراین یادآوری‌ها بدون باز کردن اپ هم می‌رسند و دو بار نمی‌آیند (اعلان محلی و FCM یک tag مشترک دارند، پس اگر هر دو برسند اندروید یکی را جایگزین دیگری می‌کند). اگر FCM روی گوشی در دسترس نباشد، اپ یادآوری‌های عقب‌افتاده را خودش یک بار نشان می‌دهد.

### ۲. رویدادها — FCM (نیازمند راه‌اندازی شما)

جریان کار: ساخت ردیف رویداد در `notifications` ← تریگر `queue_push` (با pg_net) ← Edge Function `send-push` ← FCM ← گوشی. تا وقتی مراحل زیر انجام نشده، تریگر هیچ کاری نمی‌کند و اپ بدون خطا فقط اعلان محلی دارد.

1. **پروژهٔ Firebase:** در https://console.firebase.google.com یک پروژه بسازید (احتمالاً با VPN) و یک **Android app** با package name `ir.mozemehraban.unimate` اضافه کنید.
2. **فایل اپ:** `google-services.json` را دانلود و در `apps/mobile/` بگذارید (در git نیست). `app.config.js` آن را خودکار به ساخت اضافه می‌کند. سپس APK را دوباره بسازید (`npx expo prebuild --platform android --clean` و `gradlew assembleRelease`).
3. **کلید سرویس:** Project settings → Service accounts → Generate new private key (فایل JSON). این فایل محرمانه است؛ در git و چت نگذارید.
4. **Migrationها:** `npx supabase db push` (جدول `push_tokens` و تریگر).
5. **Edge Function و secretها** — یک دستور (پروژه باید با `npx supabase link` وصل باشد):
   ```bash
   npm run push:setup -- path/to/service-account.json
   ```
   اسکریپت (`supabase/scripts/setup-push.mjs`) یک `PUSH_FUNCTION_KEY` تصادفی می‌سازد، آن و کلید Firebase را به‌عنوان secret ذخیره می‌کند، `send-push` را بدون Docker مستقر می‌کند و آدرس تابع و همان کلید را در Vault می‌گذارد. کلید را چاپ نمی‌کند و اجرای دوباره همه را با کلید تازه جایگزین می‌کند.
6. **تست:** با گوشی‌ای که APK جدید روی آن است وارد شوید (توکن خودکار ثبت می‌شود)، اپ را ببندید و از حساب دیگری در همان کلاس تکلیف بگذارید. لاگ ارسال در Dashboard → Edge Functions → send-push → Logs.

### ۳. سایت — Web Push (نیازمند راه‌اندازی شما)

کاربر در **پروفایل ← اعلان مرورگر** اعلان را برای همان مرورگر روشن می‌کند: service worker سایت (`apps/web/public/sw.js`) ثبت می‌شود و اشتراک مرورگر در جدول `web_push_subscriptions` ذخیره می‌شود. همان تابع `send-push` پیام را رمزنگاری‌شده (RFC 8291) و با امضای VAPID به سرویس push مرورگر می‌فرستد (`supabase/functions/send-push/webpush.ts`، بدون کتابخانهٔ خارجی). مرورگر نمی‌تواند مثل اپ یادآوری‌ها را خودش زمان‌بندی کند، پس **یادآوری‌های کلاس و مهلت هم به مرورگرها push می‌شوند** (ولی نه به گوشی‌ها، که خودشان زمان‌بندی می‌کنند). هنگام خروج از حساب، اشتراک آن مرورگر حذف می‌شود.

- کامپیوتر (Chrome / Edge / Firefox): وقتی مرورگر باز است، حتی اگر تب سایت بسته باشد.
- اندروید (Chrome): مثل اعلان اپ.
- آیفون/آیپد (iOS 16.4+): فقط وقتی سایت با Share ← Add to Home Screen نصب شده و از آیکون آن باز شده باشد (`app/manifest.ts`).
- ⚠️ Chrome پیام را از سرور push گوگل می‌گیرد (همان نکتهٔ FCM در ایران)؛ Firefox از سرور Mozilla.

راه‌اندازی (یک بار):
```bash
npx supabase db push              # جدول web_push_subscriptions و تریگر جدید
npm run push:setup -- --web       # کلیدهای VAPID + استقرار send-push + Vault
```
اسکریپت کلید خصوصی را فقط به‌عنوان secret (`VAPID_KEYS`) ذخیره می‌کند و کلید عمومی را در `apps/web/src/lib/web-push-key.ts` می‌نویسد؛ آن فایل را commit و سایت را منتشر کنید. تا وقتی این کلید خالی است، گزینه در پروفایل دیده نمی‌شود. اجرای دوباره کلیدها را عوض نمی‌کند (برای عوض کردن: `--rotate-web`؛ مرورگرها در بازدید بعدی خودکار دوباره مشترک می‌شوند). با `--subject` آدرس سایت (برای VAPID) را می‌توان عوض کرد.

اگر روی گوشی‌های ایران FCM ناپایدار بود، فقط Edge Function عوض می‌شود (مثلاً ارسال از طریق پوشه)؛ تریگر، جدول `push_tokens` و اپ همان می‌مانند.

اسکریپت را می‌شود با هر دو اجرا کرد: `npm run push:setup -- path/to/service-account.json --web`. هر بار `PUSH_FUNCTION_KEY` تازه می‌شود و secretهایی که داده نشده‌اند دست نمی‌خورند.

## پیشنهاد (پیش از پیاده‌سازی)

**ترکیب گزینهٔ ۱ و ۲:**

1. **الان: اعلان محلی برای یادآوری‌ها.** بدون هیچ حساب و سرویسی، همین الان روی APK کار می‌کند و مهم‌ترین نیاز (یادآوری کلاس و مهلت) را پوشش می‌دهد. اپ هنگام باز شدن و هنگام برگشتن به پیش‌زمینه، یادآوری‌های ۷ روز آینده را با تنظیمات خود کاربر دوباره زمان‌بندی می‌کند.
2. **بعد: FCM برای رویدادها** (تکلیف جدید، درخواست عضویت، …). اگر تست روی گوشی‌های واقعی در ایران نشان داد FCM ناپایدار است، همان لایهٔ ارسال را به پوشه منتقل می‌کنیم؛ بقیهٔ سیستم (جدول `notifications` و توکن‌ها) تغییری نمی‌کند.

برای مرحلهٔ ۲ لازم است: ساخت پروژهٔ Firebase (توسط شما)، `google-services.json`، جدول `push_tokens` در دیتابیس، و یک Edge Function که با کلید سرویس Firebase پیام را می‌فرستد.
